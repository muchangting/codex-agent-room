# AI 协作群

用户要求群聊、让员工协作或处理协作群消息时，使用本插件。

1. 使用 `room_open` 打开内嵌群聊。默认“AI 协作群”跨 Codex 新旧聊天共享，按需要用 `room_create` 建立具体项目群。
2. 收到用户群消息后先 `room_read`，基于记录而不是猜测判断哪些任务尚未完成。
3. Codex 是调度与验收负责人。用 `room_post` 发布计划、分工、进度和最终验收。不要冒充 Gemini 或替它编造回复。
4. 需求适合分析、资料整理或独立审查时，用 `room_dispatch` 实际派给 Gemini。只提供相关材料，不包含密钥或无关私人信息。`request_id` 用同一个群消息和子任务构成稳定键，例如 `room-1-msg-12-review`，重试同一调用沿用此键，避免重复派活。
5. `queued/running` 只代表派发或执行；员工自己写入的“任务交付”和任务 `done` 才代表实际返回。等待时可用本机短暂有界等待，继续读取 `room_read`，直到交付或失败。不要结束在“已派发”上。同一任务号永不自动重新执行；确认失败原因后若需重派，用新的任务号，例如原任务号加 `-retry1`。
6. 读取 Gemini 真实交付，核实结论，必要时由 Codex 使用自身工具执行、测试。然后用 `room_review` 记录验收（accepted）或要求修订（needs_revision），写清已核实和未核实的内容，并简短回复用户。不能直接把 Gemini 的自述当验证证据。
7. Gemini 当前通过独立 Google API 进程工作，只能分析明确提供的文本，没有本机读写/终端工具。需要写代码时让它给方案或补丁文本，由 Codex 检查并落地，不能宣称它执行过命令。
8. 面板的人类消息写入成功后会通过 MCP Apps 请求当前 Codex 会话接单。宿主若拒绝，消息仍保留，用户可以点“让 Codex 接单”或在对话里说“处理协作群消息”。不能宣称插件会在 Codex 完全关闭时自动唤醒。
9. 群聊历史默认保存在 `~/.codex-agent-room/chat.db`，也可由 MCP 环境变量 `CODEX_AGENT_ROOM_DB` 指定。不得删除群、历史、目录或其他文件；任何删除都先征得用户同意。
